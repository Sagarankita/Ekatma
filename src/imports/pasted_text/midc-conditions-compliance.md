--------------------------------------------------
M28 — MIDC CONDITIONS / COMPLIANCE / RENEWAL CONTEXT
--------------------------------------------------

PURPOSE

M28 is the post-decision context screen.

Its purpose is to answer:

“What obligations, follow-up actions, validity conditions, inspections, renewals, or reporting requirements were created by this MIDC decision?”

It must NOT act as a generic compliance-management system.

It must NOT invent obligations.

It must NOT assume that every MIDC service has a renewal.

It must NOT assume that every approval has periodic reporting.

It must NOT assume that every approval requires inspection after approval.

Instead, the system should show only obligations produced by:

1. configured MIDC service rules,
2. explicit conditions attached to the recorded MIDC decision,
3. configured approval validity rules,
4. configured inspection/follow-up rules,
5. configured renewal rules,
6. configured downstream regulatory relationships.

The mental model is:

MIDC APPROVAL / ORDER
        ↓
VALIDITY IF CONFIGURED
        ↓
CONDITIONS IF CONFIGURED
        ↓
REPORTING / FOLLOW-UP IF CONFIGURED
        ↓
INSPECTION IF CONFIGURED
        ↓
RENEWAL IF CONFIGURED
        ↓
COMPLIANCE OBLIGATION IF CONFIGURED

Do not render every stage automatically.

If a stage does not exist for the current service, do not show an empty or misleading obligation.
